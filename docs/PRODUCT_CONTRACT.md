# 产品契约

2026-09-17：用户明确接受启动检查中列出的约束，授权开始 M1。

## 产品和用户
以商品为单位串联事实录入、内容制作、风险检查、人工审核、版本和导出。面向小微电商企业的方向尚待真实试点验证；当前是本地单用户个人作品，没有已验证客户或商业效果。
固定用途：服饰商品详情文案草稿，包含标题、卖点、描述、待确认信息和来源字段引用，不适配平台发布格式。
降低学习成本，不要求用户理解提示词、模型参数、Agent 或工作流。

## 平台和体验
桌面浏览器优先，本地单用户，仅监听 127.0.0.1。当前 macOS 是验证环境，其他系统和移动端不承诺已验证。
简体中文、浅色，不做多语言或原生应用。保留语义标签、键盘操作、可见焦点、足够对比度和非纯颜色错误提示。

## 范围
M1 商品结构、规则、迁移、录入/查看页面、任务和草稿数据结构，不调用模型。
M2 单一真实文本服务，事先确认供应商、模型 ID、预算及数据范围。未配置显示“生成服务未配置”。fake 仅用于明确标识的测试。
M3 编辑、版本、通过/退回、指定已通过版本的 Markdown/JSON 导出。编辑已通过版本产生新的未审批版本，历史审批保留。
M4 可靠性、授权或自制样本、真实运行记录及演示证据。
每阶段验收后才进入下一阶段。

不做通用聊天/工作流、模板市场、图片视频生成、任意文件上传、自动发布、库存订单、客服、ERP、多租户收费、RAG、A2A、LangChain、LangGraph、n8n、Dify、ComfyUI 或通用插件平台。未来客制化优先配置，不复制客户代码或预建大量抽象。

## 架构与数据
Python 3.11+、uv、FastAPI、Pydantic、Jinja2、HTML/CSS、少量 JS、SQLite、SQLAlchemy、Alembic、httpx、pytest、Ruff。
页面/API → 应用服务 → 业务规则；数据库和模型为适配器。
款号、名称必填；颜色、尺码、已确认材质和卖点允许未知，未知明确留空。不得自行补造材质、价格、折扣、性能。结构合法不等于事实正确。
任务状态和审核状态由后端分别持久化，不让模型决定审批。任务不能依赖 HTTP 存活；重启未完成任务不得标成功。外部调用有超时、长度、重试上限，不确定结果不盲目重发，不承诺 exactly-once。
本地 SQLite；密钥仅由后端环境读取，不入页面、日志、截图、Git。输入与模型输出均不可信，模板默认转义。

## 授权和环境
不执行付费调用、不上传真实客户数据、不公开部署/创建或推送公开仓库、不安装 ComfyUI/大模型、不破坏性操作 Git，除非单独授权。
项目 uv 隔离环境，测试临时数据库；不升级全局环境。无公开发布环境。

## 验收与学习
规则先失败测试再最小实现，运行 pytest/Ruff、启动验证页面或接口，记录命令与真实结果，报告文件、完成和未完成事项及手动验收步骤。
测试矩阵覆盖缺失/冲突事实、注入、错误输出、超时、重复提交、重启中断、未审核导出和编辑后审批隔离，按里程碑逐步落实。
用户在 Cursor 阅读学习，不并行开发。每个实现小节解释业务场景、关键知识、代码入口、当前进度和真实可陈述的面试证据。不得把学习演示描述成生产经验。
